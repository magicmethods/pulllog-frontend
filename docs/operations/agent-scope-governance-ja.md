# エージェント職掌ガバナンス

## 目的

- frontend エージェントによる無断の越境編集を防止する
- backend / contract 変更が必要になった場合のエスカレーションと申し送りを標準化する
- dirty worktree や差分混在状態でも、インシデント時の説明責任を明確に保つ

## 既定スコープ

- Frontend エージェントは `frontend/` 配下のみを作業対象とします。
- `backend/` および `contract/` は、ユーザーが当該リクエスト内で明示的に許可した場合を除き、参照専用とします。

## 必須ゲート

`backend/` または `contract/` を変更する編集やコマンドを実行する前に、以下をすべて満たす必要があります。

1. 越境変更が必要であることが明示されていること
2. ユーザーが同一リクエストスレッド内で明示的に許可していること
3. どのファイルとどのコマンドが対象かをエージェントが確認していること

いずれかが欠ける場合、実装は停止しなければなりません。

## 未許可時に必要な handoff packet

backend / contract 変更が必要でも許可されていない場合は、以下を含む handoff packet を返します。

- 必要な backend / contract 変更内容
- 影響を受ける endpoint、runtime 挙動、frontend case
- 必要な検証内容（テスト、smoke check、E2E case）
- rollback 観点とリスクメモ

## 許可済み実行時に必要な記録

越境編集が明示許可の上で実行された場合は、同一ターン内で必ず以下を記録します。

- ファイル単位の変更要約
- 変更意図と挙動差分
- 実施した検証と未検証箇所
- 既知の残留リスク

## Dirty Worktree の扱い

- 変更済みファイルがすべて今回タスク由来だと仮定してはいけません。
- 今回タスクで高確度に触った変更と、既存差分を区別してください。
- 帰属が不確かな場合は、報告書内でその不確実性を明記してください。

## インシデント対応の最低要件

職掌違反、またはその疑いがある場合は、最低限以下を実施します。

1. それ以上の越境編集を停止する
2. ファイル単位のインシデント申し送り報告書を作成する
3. 以下のガバナンス規則を追加または更新する
   - `AGENTS.md`
   - `.github/copilot-instructions.md`
   - 関連する `.github/agents/*.agent.md`
4. ユーザーの指示があるまで、実装を再開しない
