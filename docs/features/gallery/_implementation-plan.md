## 課題理解サマリ
- FE-001 で API キーと CSRF トークンを扱う認証プラグインを確認・強化し、失効時のリトライまで含めて安定させることが前提。
- ギャラリー一覧と詳細導線（FE-002/005/006）を段階的に整え、フィルタ・無限スクロール・モーダル表示で資産閲覧を完結させる。
- アップロードダイアログとタグ入力（FE-004/007）はバリデーションと i18n を揃えつつ、資産更新シナリオとの連動を整理する。
- 使用量メーター（FE-003）は 30 秒ポーリングの妥当性を再検証し、アップロード完了や閲覧起点での即時更新方法を検討する。
- OpenAPI スキーマ更新（FE-008）は `api-schema.yaml` との整合を優先し、自動生成ワークフロー導入の必要性を再評価する。
- private/unlisted 資産の TTL 管理とダウンロード導線（FE-006/009）はバックエンドの署名付きURL仕様と合わせて UX を定義する。

## 最終対応優先順案
1. **FE-G1 ギャラリーAPI基盤整備（FE-001・FE-008統合）**  
   - 既存の `useAPI`／`useCsrfStore` の挙動確認と補強、`api/endpoints.ts`・`server/api` にギャラリー系ルートを追加し、型定義や Pinia ストアの骨組みを `types/`／`stores/` に用意する。  
   - 目的: 以降のUI実装が依存するデータ取得経路とセキュリティ要件を先に固める。
2. **FE-G2 ギャラリー一覧・フィルタUI基盤（FE-002・FE-007再編）**  
   - `/pages/gallery/index.vue`（想定）で無限スクロール・フィルタ・空状態・タグ補完UIを構築し、FE-G1 のストアを利用した一覧表示を実装する。  
   - 目的: 利用者が資産を探索できる最小画面を確立し、後続機能の検証土台とする。
3. **FE-G3 使用量メーターと更新戦略（FE-003）**  
   - `/gallery/usage` ポーリングの是非を見直し、アップロード完了／画面活性化時の即時更新フローを導入。メーターコンポーネントをレイアウトへ組み込む。  
   - 目的: 容量管理のUXを早期に確立し、アップロードや詳細編集と整合させる。
4. **FE-G4 アップロードフローとバリデーション（FE-004・FE-007統合）**  
   - ドラッグ&ドロップ対応のアップロードダイアログ、バリデーション／i18n、成功時の一覧・使用量リフレッシュ、タグ入力コンポーネントを実装。  
   - 目的: コンテンツ追加の主導線を整備し、FE-G2/3 と連携させる。
5. **FE-G5 資産詳細・編集/配信強化（FE-005・FE-006・FE-009統合）**  
   - 詳細モーダル、署名付きURL TTL 監視と再フェッチ、visibility 更新・削除、private/unlisted 向けダウンロード導線と共有リンク仕様を実装。  
   - 目的: 資産運用の完結したUXとセキュリティ挙動を仕上げる。

## メモ
- BE側で visibility=private / unlisted の資産は `url` 系フィールドに署名付きURLを返す。フロントは TTL 監視・再フェッチを担保する。
- 認証フローは APIキー＋CSRF トークンの二段構成。CORS 環境のためブラウザCookie送信は行わない。
