# FE-G2 ギャラリー一覧・フィルタUI基盤（FE-002・FE-007再編）

## 背景
- ギャラリー閲覧の起点となる一覧ページが未実装であり、既存の `/pages` 配下にも対応ルートが存在しない。
- フィルタ条件（期間・タグ・キーワード・ログID）や無限スクロールが要件化されているため、UI/UX とデータ取得レイヤを同時に設計する必要がある。
- タグ補完コンポーネント（FE-007）はアップロード／編集と共用予定のため、一覧側でも UI 骨組みと補完データ取得の仕組みを先に実装する。

## 対応範囲
- `pages/gallery/index.vue`（新規）で一覧画面を構築。レイアウトは既存ダッシュボードと整合をとり、ヘッダ・フィルタ・カードグリッド・空状態を実装。
- スクロール終端での追加読込（Intersection Observer or PrimeVue VirtualScroller 等）を用いたページネーションの実装。
- フィルタフォーム（期間：プリセット＋任意入力、タグ：補完付き複数選択、キーワード：入力欄、ログID：選択／検索）の状態管理を Pinia ストアへ連携。
- サムネイル表示コンポーネント（`components/gallery/GalleryAssetCard.vue` 仮称）を作成し、TTL 切れ時のプレースホルダ対応は簡易的に（詳細挙動は FE-G5）。
- ローディング・エラー・空状態の表示を国際化文言に含め、`i18n/locales/ja.ts` へ追加。

## 主なタスク
- 画面用 Layout/Section コンポーネントの選定（既存の `layouts/default.vue` を流用するか、ギャラリー専用を追加するか判断）。
  - 回答: レイアウトは `layouts/default.vue` 所属の `pages/gallery.vue` をページコンポーネントとする。
- Pinia ストアのフィルタ状態と API 呼び出しパラメータのマッピング（`limit` / `cursor` 等）を定義。
- スクロールイベントの最適化（連続発火防止、バックエンドの rate limit を考慮した待ち時間）を実装。
- タグ補完データをローカルキャッシュ（メモリ or IndexedDB）する仕組みを用意し、API 負荷を抑制。
- PrimeVue or Tailwind コンポーネントを活用したフィルタUIのスタイル調整とアクセシビリティ確認。

## 確認事項
- デフォルトのソート順（例: `uploadedAt` desc）や 1 回の取得件数（例: 20 件）に既定値はありますか？
  - 回答: デフォルトのソート順は `uploadedAt` desc で。1回の取得件数は 10 件を規定値にする。
- 期間フィルタは「プリセット（7日/30日など）＋任意日付レンジ」を必須としますか、それともプリセットのみで良いですか？
  - 回答: 当初はプリセットのみで良い。プリセットは 7日/30日/90日/全期間 の4種で。
- タグ補完はバックエンドAPIが存在しますか？ 存在しない場合、フロント側で一覧取得結果のみから補完を生成して問題ないですか？
  - 回答: タグ補完用のバックエンドAPIはありません。当初はフロント側の取得結果のみから補完するでOk。
- ログIDフィルタは既存のログ一覧APIとの連携が必要ですか？ オートコンプリートに使用するAPIがあれば情報共有をお願いします。
  - 回答: アップロード画像からログIDを辿って対象ログの履歴登録へショートカットできる機能は欲しいが、今のところログIDでのフィルタは想定していない。前述の要望を満たすにあたってログ一覧APIとの連携が必要でなければ連携は不要です。
- 空状態の表示文言・ガイド（例: 「まずはアップロードしましょう」）に既存トーン&マナー指針はありますか？
  - 回答: 当面「アップロードされた画像はありません」の結果通知のみで構いません。
