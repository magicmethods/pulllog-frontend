# FE-G3 使用量メーターと更新戦略（FE-003）

## 背景
- `/gallery/usage` エンドポイントを利用する使用量メーターは未実装であり、30 秒ポーリング要件の妥当性も未検証のまま。
- アップロード完了時やギャラリーページ表示時に即座に残容量が反映されることが重要で、無駄なポーリングを避けつつ UX を確保する戦略が必要。
- フロント全体で容量情報を共有できるよう、Pinia ストアや composable を通じてメーター表示・更新の基盤を整える。

## 対応範囲
- `components/gallery/GalleryUsageMeter.vue`（新規）でゲージ表示・閾値に応じた警告スタイルを実装。
- `stores/useGalleryStore.ts` に使用量状態（`bytesUsed`, `maxBytes`, `assetCount` など）とフェッチロジックを追加。
- アップロード／削除／詳細編集の成功時に使用量ストアを再フェッチするイベントフックを準備。
- `onVisibilityChange` やタブ復帰時の自動リフレッシュ処理を実装し、バックグラウンド時はポーリングを停止。
- メーターを表示する場所（例: `/gallery` ページ上部、あるいは共通サイドバー）に組み込み。

## 主なタスク
- ポーリング方針を決定（例: 初回ロード＋タブアクティブ時 60 秒間隔、アップロード直後は即再フェッチ）。
- バックエンドのレスポンス構造を確認し、i18n 文言（残容量・使用率・ファイル数）を整備。
- ネットワークエラー時のリトライ戦略（指数バックオフ or 次回ポーリングまで待機）を実装。
- 使用量データを `localStorage` などへキャッシュするか検討し、必要なら TTL を設定。
- メーターコンポーネントのユニットテスト（計算ロジック・スタイル判定）を作成（可能なら `@testing-library/vue` 使用）。

## 想定変更ファイル
- `components/gallery/GalleryUsageMeter.vue`（新規）
- `stores/useGalleryStore.ts`
- `composables/useGalleryApi.ts`（必要に応じて）
- `pages/gallery/index.vue`（メーター配置）
- `i18n/locales/ja.ts`

## 確認事項
- ポーリング間隔の上限／下限（例: 最低 30 秒、最大 2 分など）について制約はありますか？
- 使用率が閾値を超えた場合の通知方法（色変更・トースト表示など）の希望はありますか？
- メーターはギャラリーページ以外（例: ダッシュボード）にも表示する予定がありますか？
- レスポンスで返る `maxBytes` と `assetCount` の定義（プラン上限 or 現在値）に不確定要素はありますか？
- タブ非アクティブ時のポーリング停止条件（`document.hidden` チェック等）について、既存のルールがあれば共有をお願いします。
